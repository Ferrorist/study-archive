# 결측률 계산 및 처리 전략

## 결측치란? (Missing Value)
결측치는 "있어야 할 데이터가 비어 있는 상태" 라고 볼 수 있다.

예를 들어:<br>
* 설문조사에서 나이 칸을 비워둔 응답
* 센서가 특정 시점에 값을 못 찍어서 NaN으로 들어간 값
* CSV를 읽었는데 값이 "", "NA", "null" 등으로 들어간 칸

Pandas 기준으로는 보통:<br>
* `NaN` (Not a Number)
* `None`
* 일부 문자열 `"NA"`, `"NaN"` (전처리 과정에서 전처리 필요)

이런 것들이 결측으로 간주된다.


<br>

## 결측치가 분석·모델링에 끼치는 영향

### 1) 단순 통계/EDA에 끼치는 영향
* `df.mean()`, `df.std()` 등은 기본적으로 `NaN`을 자동으로 무시하지만,<br>
결측 비율이 크면 평균 자체의 데이터가 "진짜 성격"을 잘 못 나타낸다.

* `groupby`나 `agg`등을 할 때 결측이 많으면 특정 그룹의 통계가 왜곡될 수 있다.
ex) 나이 결측이 특정 연령대에만 몰려 있다면, 평균 나이가 이상해진다.

### 2) 시각화에 끼치는 영향
* 히스토그램, 박스플롯을 그릴 때 결측이 많으면,
  * 샘플 수가 줄어서 분포가 이상해 보임.
  * 특정 구간(ex. 고령층)의 데이터가 빠져 있으면 "왜곡된 분포"로 보일 수 있음.


### 3) 머신러닝 모델에 끼치는 영향
* 많은 **기본 모델은 NaN이 있으면 아예 학습이 되지 않음.**
  * `sklearn`의 LogisticRegression, SVC 등은 NaN을 허용하지 않는다.
* 결측치를 처리하지 않는다면:
  * 에러 발생 (코드 자체가 실행되지 않음)
  * 일부 라이브러리는 NaN을 자체 처리하긴 하지만, 그 로직을 모르면 결과 해석이 위험.

<br>

## 결측치가 발생하는 이유
결측의 **원인을 이해하는 게, 처리 전략을 고르는 기준**이 된다.

### 1) 데이터 수집 과정 문제
* 설문 응답자가 민감한 질문(소득, 나이 등)을 비워둔 경우
* 기계(센스, 로그)가 순간적으로 고장이 나서 값을 못 보낸 경우
* 웹 크롤링 중 일부 페이지에서 값이 없던 경우

### 2) 데이터 통합/전처리 문제
* 여러 테이블을 `merge`/`join` 하면서 매칭이 안 되는 행이 생김.
  * → 예: 고객 테이블에는 있지만, 주문 테이블에는 없는 사람
* 타입 변환 중 파싱 실패 → `NaN`으로 변환됨.


### 3) 설계 상 "원래 정보가 없음"
* 결혼 여부: 미혼인 사람은 "배우자 이름"이 존재할 수 없음 → 자연스러운 결측
* 탑승하지 않은 승객의 "좌석 번호", 사지 않은 사람의 "가격"

이처럼 **"빠져 있으면 안되는 값"인지, "원래 없을 수도 있는 값"인지 구별**하는 게 중요하다.

<br>

##  결측이 나타나는 패턴
보통 3가지로 분류한다.

### 1) MCAR (Missing Completely At Random)
* 완전히 랜덤하게 빠짐
* 결측 여부가 어떤 변수와도 연관이 없음
* 예: 설문시 인쇄 오류로 랜덤하게 한 칸씩 비어 있는 경우
* 해당 경우는 삭제(drop) 해도 큰 편향이 없을 수 있음.

### 2) MAR (Missing At Random)
* "완전 랜덤은 아니고", 다른 관측된 변수와 관련이 있음.
* 예: 나이가 많을수록 소득을 잘 안 적는다. → 나이와 결측이 관련됨.
* 이 경우 단순 삭제는 위험, 적절한 대체(imputation) 필요

### 3) MNAR (Missing Not At Random)
* 결측 자체가 그 변수의 값과 직접적으로 관련
* 예: 소득이 낮거나 높을수록 소득을 안 적는 사람이 많음.
* 이 경우는 단순 평균 대체가 매우 위험할 수 있음.

실무에서는 **‘결측이 랜덤한지, 특정 그룹에 쏠려 있는지’ 정도는 항상 확인**해야 한다.

<br>

## 결측률 계산
pandas 기준으로는 아래와 같이 자주 사용한다.

```python
# 컬럼별 결측 개수
df.isnull().sum()

# 컬럼별 결측 비율
df.isnull().mean() # 0~1 사이 비율
df.isnull().sum() / len(df) # 위와 동일


# 결측률을 보기 좋게 DataFrame으로
missing_rate = (df.isnull().sum / len(df)).reset_index()
missing_rate.columns = ["column", "missing_rate"]
print(missing_rate)
```

* 결측률 0~5% : 보통 큰 문제 없음 (삭제도 고려 가능)
* 결측률 5~30% : 전략적으로 채울지/삭제할지 고민
* 결측률 30% 이상: 그 컬럼 자체를 버릴지, 강하게 가정하고 채울지 고민

**중요 포인트:**<br>
"무조건 채운다/무조건 버린다" 가 아니라,
해당 컬럼이 분석 및 모델에서 중요한가? 결측이 특정 그룹에 치우쳐 있나? 이 2 가지를 기준으로 판단한다.

<br>

## 결측치 처리 전략 개요

1. 삭제 (Drop)
* 행 삭제 (dropna(axis=0))
* 열 삭제 (dropna(axis=1) 또는 컬럼 직접 drop)

2. 단순 대체(Simple Imputation)
* 평균(mean), 중앙값(median), 최빈값(mode)
* 고정값(0, "Unknown", "기타" 등)

3. 고급 대체(모델 기반, 다중 대체 등)
* KNN Imputer, 회귀 기반 대체, MICE 등

4. 결측 자체를 정보로 사용
* 결측 여부를 0/1 플래그로 만들어 feature에 포함

## 각 전략을 언제 쓰는가?

1) 삭제(dropna)를 쓰는 경우
* 데이터가 충분히 많고, 결측 비율이 낮다.
* 결측이 완전히 랜덤(MCAR)에 가깝다고 볼 수 있을 때
* 해당 컬럼이 메인이 아니고, 조금 손실이 나도 괜찮을 때
```python
# 아무 컬럼이나 결측이 하나라도 있으면 행 삭제
df_clean = df.dropna()

# 특정 컬럼에 결측이 있는 행만 삭제
df_clean = df.dropna(subset=["Age", "Fare"])
```

단점:
* 데이터가 줄어들어서 모델이 "학습할 수 있는 정보량"이 줄어듦.
* 결측이 특정 집단에 몰려 있으면 심한 편향 발생 가능

2) 평균/중앙값/최빈값 대체를 쓰는 경우

(1) 평균 대체
* 연속형 변수, 이상치가 많지 않을 때 사용

장점: 쉽고 빠름, 모델 학습이 가능해짐.

단점: 분산을 줄인다. 결측이 많을 경우, 데이터 분포 왜곡 -> 값들을 평균 쪽으로 몰려 버리게 함.


(2) 중앙값 대체
* 이상치가 많을 때 훨씬 안전
* 예: 소득, 가격처럼 꼬리 두꺼운 분포


(3) 최빈값 대체
* 범주형 변수에 사용


3) 고정값으로 채우기
* "값이 없다는 것 자체가 정보"일 때 자주 사용
